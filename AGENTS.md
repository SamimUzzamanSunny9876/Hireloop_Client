# HireLoop client

Next.js 16 App Router + React 19 + Tailwind v4 + shadcn (`base-nova`) + better-auth/MongoDB. Uses npm (`package-lock.json`). No `src/` directory; `@/*` maps to the repo root. There is no test suite, test runner, or CI workflow — don't invent test commands.

## Structure

- `app/layout.tsx` owns the global chrome: `Navbar`, `<main>`, and `Footer` wrap every route. Don't re-add them per page.
- The homepage is `app/page.tsx`, composing section components: `Banner`, `Features`, `Pricing`, `NextRole` in `components/`.
- `app/(auth)/sign-in` and `app/(auth)/sign-up` are empty placeholder pages. The navbar and CTA link to `/get-started`, which has no route yet.

## Commands

- `npm run dev` — dev server at `http://localhost:3000`.
- `npm run typecheck` — `tsc --noEmit`; passes today.
- `npm run lint` — flat-config ESLint over the repo. Full runs currently fail only in `components/ui/carousel.tsx` and `hooks/use-mobile.ts` (`react-hooks/set-state-in-effect`); lint only changed files with `npx eslint <paths>` so these don't mask new issues.
- `npm run format` — Prettier for `**/*.{ts,tsx}`. Prefer `npx prettier --write <paths>`; the script rewrites the whole repo.
- `npm run build` — production build.
- Formatting is non-default: no semicolons, double quotes, LF, print width 80, and Tailwind classes auto-sorted via `cn`/`cva` and `app/globals.css`.

## UI and styling

- shadcn style is `base-nova` in `components.json`: primitives come from `@base-ui/react`, not Radix. Add components with `npx shadcn@latest add <name>`; they land in `components/ui/`.
- Tailwind v4 is CSS-first in `app/globals.css` (`@import "tailwindcss"`, `@theme inline`). There is no `tailwind.config.*`; add theme tokens there.
- `lib/utils.ts` re-exports `cn` from the `cn` npm package, but generated shadcn files import `cn` directly from `"cn"`. Both work — don't "fix" those imports.
- `lucide-react` is v1.69 and no longer ships brand icons. `Facebook`, `Linkedin`, `Github`, etc. are undefined; inline an SVG instead.
- The marketing sections intentionally hardcode the dark palette (`#07070b`, `#7c6cf6`, white opacity values) rather than semantic tokens, so they stay dark. Keep that pattern when adding sections.
- Images live in `app/images/` and are imported statically for `next/image`. `types/next-images.d.ts` supplies the PNG module types because the generated `next-env.d.ts` is gitignored.
- Dark mode is class-based via `components/theme-provider.tsx`; pressing `d` toggles it (ignored while typing).

## Auth (better-auth + MongoDB)

- Server config: `lib/auth.ts`. Client: `lib/auth-client.ts`. Catch-all route: `app/api/auth/[...all]/route.ts` — keep this path or better-auth's client calls break.
- MongoDB is hard-coded to local `mongodb://localhost:27017/database`, database `Hireloop`; no `MONGODB_URI` env is read. Local MongoDB must be running for auth to work.
- `.env` currently defines only `BETTER_AUTH_SECRET` and `BETTER_AUTH_URL`. GitHub/Google providers are always registered, so `npm run build` warns about missing client IDs until `GITHUB_CLIENT_*` / `GOOGLE_CLIENT_*` are added.
- `lib/auth-client.ts` creates two clients: `authClient` gets `BETTER_AUTH_URL`, while the exported `signIn`/`signUp`/`useSession` come from a separate bare `createAuthClient()`. Also, non-`NEXT_PUBLIC_` vars aren't available in browser code, so that base URL is effectively undefined client-side.
